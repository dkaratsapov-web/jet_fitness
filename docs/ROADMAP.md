> Текущий интерфейс Mini App — **намеренно каркасный** (функциональные заглушки).
> Его предстоит заменить на фирменный вид.

- [ ] **Премиальный дизайн** Mini App: продуманный UI/UX, анимации, состояния,
      мобайл-first, светлая/тёмная темы под Telegram.
- [ ] **Брендбук приложения**: логотип, палитра, типографика, иконки,

- [ ] Применить бренд ко всем экранам (владелец / тренер / клиент) и к боту

параллельно силами дизайнера — макеты → компоненты → внедрение.

## Статус по фазам (ТЗ §12)

### Фаза 0 — Каркас ✅ (развёрнуто в проде)
- Монорепо, Prisma-схема, бот-скелет, API с валидацией initData, Mini App.
- Инфраструктура в Yandex Cloud (Terraform) + автодеплой (GitHub Actions).
- Работает в Telegram: вход через initData, роли **владелец / тренер / клиент**.

### Фаза 1 — MVP (в проде, продолжается)
- [x] CRM клиентов + приглашения (deep-link инвайты, самостоятельная авторизация клиента)
- [x] Библиотека упражнений + конструктор программ + выдача клиенту
- [x] Клиент: тренировка (выполнение дня программы) + отметка подходов/веса + история
- [x] Прогресс: вес / % жира / замеры + динамика + **фото прогресса**
      (Object Storage, presigned-upload, приватный бакет, галерея у тренера)
- [x] Check-in (сон/энергия/настроение/приверженность + комментарий, ответ тренера)
- [x] Оплаты: подписки, отметка оплаты, комиссия платформы, выручка тренера и владельца
- [x] Уведомления через бота (выдача программы, check-in, ответ тренера, новый клиент)
- [x] Онбординг-анкета клиента (цель / пол / рост / дата рождения при первом входе)
- [x] Графики динамики (вес + объём тренировок, SVG-линия; полироваться будут с дизайном)
- [x] Видео-разбор техники (загрузка видео клиентом + комментарии тренера)

#### ⛳️ Решения владельца
- [x] **Хранилище файлов** — Yandex Object Storage (приватный бакет `uploads`,
      presigned PUT/GET, SigV4). Фото прогресса + видео техники — готово.
- [ ] **Реальный платёжный провайдер** — по решению владельца пока **не
      подключаем**; оплаты учитываются вручную (`provider: "manual"`). Схема
      (`Payment.provider` / `providerRef`, идемпотентность) готова под вебхук.

### Фаза 3 — Модуль здоровья (за флагом; включать после юр. проработки)
Код готов и задеплоен, но **выключен в проде** (`HEALTH_MODULE_ENABLED=false`).
- [x] Флаг `HEALTH_MODULE_ENABLED` + шифрование (AES-256-GCM, `HEALTH_ENCRYPTION_KEY`)
- [x] Явное согласие клиента (revocable), гейт всех health-роутов
- [x] Анализы: ввод, графики по маркеру, референс-диапазоны; значение и ключ
      файла зашифрованы at-rest; тренеру — только чтение и только при согласии
- [x] БАДы: нейтральный журнал + отметка приёма + дисклеймеры
- [x] Экспорт всех данных (JSON) + жёсткое удаление
- [ ] OCR бланков анализов (опция), напоминания о приёме (см. бэклог)
- [ ] Админ-панель платформы, модерация

> **Как включить** (после юридической проработки): задать в секретах репозитория
> `HEALTH_ENCRYPTION_KEY` (32 байта, hex/base64) и `HEALTH_MODULE_ENABLED=true`,
> затем передеплоить. Без ключа модуль остаётся недоступным даже при флаге.

## 💡 Идеи / бэклог

- [ ] **Напоминания-расписание** — регулярные пуши в бота: приём БАДов и
      таблеток (по расписанию из `SupplementLog`/`SupplementIntake`),
      предстоящая тренировка, время взвешивания/замеров, вода, дедлайн
      check-in. Клиент настраивает время; движок шлёт через релей, отмечает
      «принято/выполнено». Технически — планировщик (cron в Cloud Functions
      или отдельный триггер) + модель расписаний. Согласовать формулировки для
      БАД/таблеток с юридической частью (не медицинские рекомендации).
- [ ] **Интеграция с фитнес-браслетом / шагомером** — подтягивать шаги,
      активность, пульс, сон и калории из носимых устройств и приложений:
      Apple Health (HealthKit), Google Fit / Health Connect, Mi Band / Zepp,
      Garmin, Fitbit. Данные о шагах/активности идут в прогресс и в расчёт
      суточных энергозатрат (для целей по калориям). Требует нативного моста
      или стороннего агрегатора (напр. Terra API / Rook) — Telegram Mini App
      напрямую к HealthKit/Google Fit доступа не имеет. Оценить объём отдельно.
